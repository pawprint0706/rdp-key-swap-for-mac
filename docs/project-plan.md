# Mac RDP 키 재해석 프로그램 계획

## 1. 근본 목표

MacBook에서 RDP로 Windows에 접속하면 Command는 Windows 키로, Option은 Alt 키로 전달된다. 이 프로그램은 **등록한 Mac에서 RDP로 접속했을 때만, 전달된 키를 아래 규칙으로 재해석**한다.

macOS 단축키를 Windows 단축키로 호환시키는 프로그램이 아니다. 조합에 들어 있는 문자나 실행할 기능을 판단하지 않고, 대상 modifier 키 자체만 변환한다.

## 2. 적용 조건

- 현재 사용자 세션이 RDP 접속이다.
- RDP 클라이언트 이름이 옵션에 등록한 이름 목록 중 하나와 일치한다.
- 두 조건을 모두 충족할 때만 변환한다. 그 외에는 모든 입력을 그대로 통과시킨다.

옵션의 이름은 접속 대상 Windows 컴퓨터가 아니라 **접속하는 Mac의 클라이언트 이름**이다. 현재 확인된 값은 `example-mac`이며, 하드코딩하지 않고 사용자가 여러 이름을 목록으로 등록·삭제하고 저장할 수 있게 한다.

각 이름은 앞뒤 공백을 제거하고 대소문자를 구분하지 않는 완전 일치로 비교한다. 빈 항목은 제외하고 중복 이름은 하나로 취급한다. 목록 중 하나라도 일치하면 적용하며, 목록이 비어 있거나 일치하는 이름이 없으면 변환하지 않는다. 부분 일치나 와일드카드는 사용하지 않는다.

재접속으로 클라이언트가 바뀌면 조건을 다시 판정한다. 클라이언트 이름을 확인할 수 없으면 변환하지 않는다. OS나 RDP 앱 종류를 추측하여 활성화하지 않는다.

## 3. 유일한 키 변환 규칙

| MacBook에서 누른 키 | RDP로 수신한 키 | 프로그램이 재해석할 키 |
|---|---|---|
| Control | Ctrl | Ctrl 그대로 |
| Command | Windows 키 | Alt |
| Option | Alt | Windows 키 |
| 그 외 | 해당 입력 | 그대로 |

좌우 구분이 전달되는 경우 유지하며, 누름과 뗌에 동일한 규칙을 적용한다. 다른 modifier나 일반 키와 함께 눌러도 이 규칙은 바뀌지 않는다.

단축키별 예외, 앱별 동작, 조합 감지, 별도 명령 실행은 추가하지 않는다. 변환된 modifier 조합의 의미는 Windows와 해당 앱이 결정한다.

## 4. 한국어 101키에서 주의할 점

이 문서는 한국어 101키 **종류 1을 대표 사례로 설명**한다. 종류 1에만 적용되는 프로그램이라는 뜻은 아니다. 종류 2·3에서도 동일한 키 변환 규칙을 적용하며, 한/영·한자 동작은 Windows에 설정된 레이아웃의 해석에 맡긴다. 종류별 전환 키를 프로그램이 별도로 지정하거나 강제하지 않는다.

한국어 101키 종류 1에서는 우측 Alt가 한/영 전환키로, 우측 Ctrl이 한자키로 인식된다. 따라서 가상 키 이름만 보고 처리하면 우측 입력의 의미를 잘못 해석할 수 있다.

우측 Command에서 온 우측 Windows 키는 우측 Alt로 변환한다. 이 결과 한국어 101키 종류 1에서 발생하는 한/영 전환은 정상적인 키 해석 결과이며 차단하지 않는다.

우측 Control은 Ctrl 유지 원칙을 따른다. 한국어 101키 종류 1에서 이를 한자키로 해석하는 기존 동작도 보존한다. 별도의 한자 변환 기능을 추가하거나 일반 Ctrl 동작으로 강제하지 않는다.

구현 전에 실제 RDP 입력의 가상 키 코드, 스캔 코드, 좌우 구분, extended 플래그를 확인한다. 우측 Alt·우측 Ctrl이 도착하는 경로와 키보드 레이아웃에 의해 이미 한/영·한자 입력으로 해석된 경로를 구분해야 한다.

- 실제 Alt 입력으로 확인되면 좌우 모두 위의 Alt→Windows 규칙을 적용한다.
- 변환한 키는 가상 키 코드가 아니라 **스캔 코드 기준**으로 주입하여, 활성 키보드 레이아웃이 물리 키와 동일하게 해석하도록 한다. 가상 키를 직접 지정하면 레이아웃 변환을 건너뛰어, 한국어 101 종류 1에서 우측 Alt가 한/영이 아닌 일반 Alt로 전달된다.
- 한/영 코드로 보이는 입력을 근거 없이 Alt 또는 일반 한/영 키로 단정하지 않는다. 실제 전달 경로를 확인하여 변환 대상인지 판별한다.
- 독립적인 한/영·한자 키 입력 등 변환 대상이 아닌 입력은 변경하지 않는다.
- 우측 Option을 무조건 한/영 전환키로 지정하는 별도 정책은 두지 않는다.
- IME 전환 기능을 따로 만들거나 Windows 키보드 레이아웃 설정을 바꾸지 않는다.

목표는 한/영 전환 기능을 추가하는 것이 아니라, **101키 레이아웃의 해석까지 감안하여 동일한 키 변환 원칙을 정확히 적용하는 것**이다. 실제 RDP 경로에서 원래 키를 구분할 정보가 사라진다면 그 한계를 명시하고, 임의의 예외로 대체하지 않는다.

## 5. 최소 구현 계획

1. 사용자 세션의 단일 트레이 상주 앱을 만들고, 여러 클라이언트 이름의 등록·삭제·저장 및 로그인 시 자동 실행 옵션을 제공한다.
2. WTS API로 현재 RDP 세션과 클라이언트 이름을 확인한다.
3. 실제 MacBook RDP 입력을 관측하여 좌우 modifier 및 한국어 101키의 전달 형태를 확인한다.
4. 조건이 일치할 때 키보드 입력을 가로채고, 지정한 키만 변환하여 전달한다.
5. 실제 RDP 접속에서 변환 결과와 조건 불일치 시 원본 유지 여부를 확인한다.

개발 스택은 **C# / .NET + Windows Forms + Win32 API**를 기본안으로 한다.

- C# / .NET: 키 변환 상태와 설정 관리.
- Windows Forms: 최소 설정 화면과 상주 실행을 위한 메시지 루프.
- Win32 API(P/Invoke): `WTSQuerySessionInformation`으로 RDP 세션·클라이언트 이름 조회, WTS 세션 알림으로 접속 변경 감지, `WH_KEYBOARD_LL`로 입력 가로채기, `SendInput`으로 변환 입력 전달.

별도의 C++ 모듈이나 키보드 드라이버는 기본안에 포함하지 않는다. 단축키 편집기, 앱별 프로필도 이번 계획에 포함하지 않는다.

키 눌림/뗌 대응, 원래 입력과 변환된 입력의 상태 관리, 합성 입력의 재변환 방지, 세션 변경 시 눌림 상태 정리는 부가기능이 아니라 키 변환 자체의 정확성을 위한 구현 조건이다.

### 실행 형태와 자동 시작

- Windows 서비스가 아닌 **사용자 세션의 단일 트레이 상주 앱**으로 구현한다. 키 변환과 설정 화면을 같은 프로세스에서 제공한다.
- 서비스는 세션 0에 격리되어 사용자 키 입력을 직접 처리할 수 없다. 서비스를 도입해도 별도 사용자 세션 프로세스가 필요하므로, 이 프로젝트에서는 서비스와 프로세스 간 통신을 추가하지 않는다.
- 설정에 **“Windows 로그인 시 자동 실행”** 옵션을 제공한다. 부팅 시 서비스로 실행하는 것이 아니라 사용자 로그인 시 해당 세션에서 시작한다.
- 자동 실행은 사용자별 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 값의 등록·해제로 관리한다. 다른 시작 항목은 변경하지 않는다.
- 자동 실행 시 설정 창을 열지 않고 트레이로 시작한다. 트레이 메뉴에서 설정 열기와 종료를 제공한다.
- 같은 사용자 세션에서는 중복 실행을 막는다. 서로 다른 사용자 세션에서는 각각 독립적으로 실행하여 자신의 RDP 접속 정보로 적용 여부를 판단한다.
- 기존 세션으로 RDP 재접속 시 새 프로세스 실행에 의존하지 않고, 실행 중인 앱이 세션 변경을 감지하여 적용 조건을 다시 확인한다.
- 기본적으로 일반 사용자 권한으로 실행한다. 관리자 권한 앱에 대한 `SendInput`의 UIPI 제한은 별도 제약이며, 서비스 도입으로 해결되는 문제가 아니다. 로그인 화면이나 UAC 보안 데스크톱의 키 입력 처리는 지원 범위에 포함하지 않는다.

## 6. 검증 기준

- 등록한 이름 목록 중 어느 하나와 일치하는 RDP 세션에서만 변환된다. 목록의 첫 항목뿐 아니라 다른 항목과 일치하는 경우도 확인한다.
- 로컬 접속, 빈 목록, 모든 이름 불일치, 클라이언트 정보 조회 실패 시 입력이 바뀌지 않는다.
- 이름의 대소문자·앞뒤 공백 차이와 중복 항목이 판정 결과를 바꾸지 않으며, 저장한 이름 목록은 재실행 후에도 유지된다.
- Control은 유지되고, Command에서 온 Windows 키는 Alt로, Option에서 온 Alt는 Windows 키로 전달된다.
- 좌우 입력과 누름/뗌이 일관되며, 여러 modifier를 함께 사용해도 키가 눌린 상태로 남거나 조기에 해제되지 않는다.
- 한국어 101키 환경에서 우측 Command→우측 Alt 변환에 따른 한/영 전환을 확인한다. 우측 Option→우측 Windows 키 변환에는 원래 우측 Alt의 한/영 동작이 남거나 중복 발생하지 않아야 한다.
- 한국어 101키 종류 1에서 우측 Control의 한자키 동작이 유지되는지 확인한다.
- 재접속 후에는 새 클라이언트 이름을 기준으로 적용 여부가 갱신된다.
- 자동 실행 옵션을 켜면 현재 사용자의 시작 항목이 등록되고, 끄면 해당 앱의 시작 항목만 제거된다.
- 자동 실행을 켠 상태에서 로그아웃 후 다시 로그인하면 설정 창 없이 트레이로 시작한다. 끈 상태에서는 로그인해도 자동으로 실행되지 않는다.
- 같은 세션에서 다시 실행해도 키보드 훅이 중복 설치되지 않으며, 서로 다른 세션의 실행·설정 화면·접속 판정은 섞이지 않는다.
- 트레이에서 설정을 열 수 있고, 종료하면 훅과 프로그램이 유지하던 키 상태를 정리한 뒤 종료된다.

구현은 `src/RdpKeySwap`에 있고, 빌드·사용·검증 방법은 `README.md`에 정리한다.
